## Claim
An agent can improve across attempts without weight updates by turning outcome feedback into written reflections stored in an episodic buffer and re-read on the next trial.
## Mechanism
- An actor attempts the task; an evaluator scores the trajectory (scalar, binary or language feedback).
- A self-reflection model converts that signal plus the trajectory into a short verbal lesson.
- Lessons go into an episodic memory buffer and are prepended to the next attempt.
- Long-term memory is a bounded sliding window of reflections.
- For code, feedback comes from self-written unit tests and compiler output.
## Evidence
- HumanEval: 91% pass@1, versus 80% for GPT-4 as stated in the abstract.
- ALFWorld: ReAct plus Reflexion completed 130 of 134 tasks over 12 consecutive trials; ReAct alone stalled between trials 6 and 7.
- HotpotQA (100 questions): baselines never recovered failed tasks across trials, while Reflexion kept improving.
- Reflexion set state of the art on all Python and Rust code benchmarks except MBPP Python.
## Limits
- Quality depends on the evaluator; flaky self-generated tests can pass wrong code (false positives), which explains the weak MBPP Python result.
- Local-minimum risk: it is policy optimisation in text and can get stuck.
- Memory is only a small sliding window, with no retrieval or curation.
## We adopt
The reflect skill writes an episodic note after a task, grounded in a real outcome signal (DESIGN.md#external-feedback-gate), stored under memory/episodic/ and reused on the next similar task (.claude/skills/reflect).
## We reject
A sliding window as the only memory, and trusting self-generated tests alone. Reflections never become semantic memory directly; they go through the inbox and curator.
