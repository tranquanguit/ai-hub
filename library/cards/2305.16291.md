## Claim
A growing library of executable, verified skills lets an LLM agent accumulate and compose abilities over time without fine-tuning or forgetting.
## Mechanism
- An automatic curriculum proposes the next task from the agent's current state.
- The model writes code for the task and refines it using environment feedback and execution errors.
- A self-verification step judges success and supplies critique when it fails.
- Only verified programs are stored in the skill library, indexed by description embeddings.
- Later tasks retrieve and compose earlier skills.
## Evidence
- Minecraft: 63 unique items in 160 prompting iterations, 3.3x more than baselines; 2.3x longer travel distance.
- Tech tree milestones unlocked up to 15.3x faster (wooden level) than prior methods.
- Ablations: removing self-verification cut discovered items by 73%; a random curriculum cut them by 93%.
- Without the skill library, progress plateaued in later stages.
## Limits
- Self-verification sometimes misses real successes; the agent can also get stuck on a skill.
- The curriculum and code hallucinate impossible items or invalid fuel.
- Needs GPT-4-level coding (15x the cost of GPT-3.5); evaluated only in Minecraft.
## We adopt
Skills enter the library only after verification, and skill-forge is the sole path that creates them (DESIGN.md#skill-library, .claude/skills/skill-forge), with a test or tool result as the check (DESIGN.md#external-feedback-gate).
## We reject
Unattended self-driven curriculum and storing code skills judged by the model alone. We also skip embedding retrieval over skills; descriptions in hot context plus the INDEX do that job.
