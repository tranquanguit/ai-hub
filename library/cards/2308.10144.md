## Claim
An agent can learn reusable natural-language insights from both successful and failed trajectories on training tasks, and recall past successes at inference, with no parameter updates.
## Mechanism
- Stage one collects experiences, with retries producing failure and success pairs.
- Stage two has an LLM compare failure/success pairs and read lists of successes, then edit an insight list.
- The LLM applies ADD, EDIT, UPVOTE, DOWNVOTE or REMOVE operators, so weak insights decay.
- At inference the full insight list is in the prompt and similar successful trajectories are retrieved as examples.
- Insights start with an importance count of two; reaching zero removes them. Humans can inspect and edit them.
## Evidence
- ALFWorld: ReAct baseline 40.3%; ExpeL retrieval-only 54.5%; ExpeL plus Reflexion 59.0%.
- Ablation: insights-only versus retrieval-only scored 36% versus 31% on HotpotQA and 50% versus 55% on ALFWorld.
- Transfer from HotpotQA to FEVER: ExpeL 70%, ReAct 63%, Act 58%.
## Limits
- Text-only observations and closed API models were tested.
- Insights fit in the context window; truly lifelong use needs retrieval over them.
- WebShop gains were weaker, near the low end of Reflexion's range.
## We adopt
Insights are extracted from successes and failures, then kept or dropped by helpful/harmful voting. The counters live in curate-learning and the retrieval index (.claude/skills/curate-learning, DESIGN.md#retrieval).
## We reject
Putting the whole insight set in every prompt, which would break the small hot context. We also do not let the model alone rank insights; votes need an external signal before promotion.
