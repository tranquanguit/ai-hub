## Claim
Treating the context window like RAM and external storage like disk, with the model paging data between them, gives the illusion of unbounded context.
## Mechanism
- Main context (system prompt, working scratch area, recent messages) is small and fixed.
- External tiers (recall of full history, archival storage) are reached only through function calls.
- Queries return paginated results, so one lookup cannot flood the context.
- Memory pressure warnings trigger eviction and recursive summarization of old messages.
- The model itself decides when to read and write memory.
## Evidence
- Deep memory retrieval on the multi-session chat dataset: GPT-4 accuracy 32.1% rises to 92.5% with MemGPT; GPT-4 Turbo 35.3% to 93.4%; GPT-3.5 Turbo 38.7% to 66.9%.
- Document QA (NaturalQuestions-Open retriever-reader): MemGPT performance does not change as retrieved context grows, while truncated fixed-context baselines degrade.
- Nested key-value retrieval: only MemGPT completes the task beyond 2 nesting levels; GPT-3.5 reaches 0% at 1 level.
## Limits
- Weaker base models (GPT-3.5) handle the function calls poorly.
- Document QA is capped by embedding retriever quality; the gold document often ranks beyond the first dozen results.
- Many tool calls cost latency and tokens.
## We adopt
Hot and cold tiers with paging through indexes: small always-loaded files, cold storage in library/full read on demand (DESIGN.md#retrieval). PreCompact writes LEDGER.md so eviction loses nothing (DESIGN.md#compaction-ledger).
## We reject
Model-driven recursive summarization as the only record, because lossy summaries cannot be verified; and a custom paging runtime, since Claude Code file reads already page.
