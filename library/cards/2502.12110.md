## Claim
Memory notes that carry keywords and tags and are linked to related notes retrieve better than flat stores.
## Mechanism
- Each new memory becomes a note with context description, keywords, tags and embedding.
- Link generation retrieves similar older notes and has the LLM decide which to connect.
- Memory evolution lets new notes update the descriptions and tags of linked old ones.
- Retrieval uses top-k similarity, then follows links to neighbours.
## Evidence
- LoCoMo long-conversation QA (F1 and BLEU-1): beats baselines for non-GPT models across categories; competitive on GPT models.
- Uses about 1,200 tokens per memory operation versus about 16,900 for LoCoMo and MemGPT baselines (the paper states 85-93% fewer).
- Ablation: removing link generation and evolution hurts most on multi-hop and open-domain; link generation alone recovers part of the gap.
## Limits
- Note quality depends on the underlying LLM; different models link differently.
- Text-only; evaluated on one dialogue dataset.
- Automatic evolution rewrites old notes, which can silently change history.
## We adopt
A `links` frontmatter field between semantic facts so related facts are found together (DESIGN.md#retrieval), set by the curator and reviewed.
## We reject
Autonomous memory evolution that edits existing notes. Contradictions go to memory/conflicts and are never overwritten (DESIGN.md#conflicts). We also skip embedding similarity for link creation.
