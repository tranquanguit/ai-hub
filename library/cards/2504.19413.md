## Claim
An extract-then-update memory pipeline, where each candidate fact is compared with similar stored memories and turned into one explicit operation, keeps long-term memory consistent at a fraction of full-context cost.
## Mechanism
- Extraction: an LLM pulls salient candidate facts from recent messages plus a conversation summary.
- Update: for each candidate it retrieves the top-10 similar memories and picks one operation: ADD, UPDATE, DELETE (contradicted) or NOOP.
- The operation is chosen by the LLM through a tool call; memories are stored as natural-language facts (a graph variant adds entities and relations).
- Retrieval at answer time uses only the selected memories, not the whole history.
## Evidence
- LOCOMO benchmark: 26% relative improvement on an LLM-as-a-Judge metric over OpenAI's memory; the graph variant adds about 2% overall.
- Versus full context: 91% lower p95 latency and more than 90% token-cost savings (abstract).
- Search latency p50 0.148 s, p95 0.200 s; the memory store takes about 7k tokens per conversation (Sec. 4).
## Limits
- The LLM itself decides DELETE for contradictions, so a wrong judgement silently destroys a fact. There is no human or external check.
- Quality is measured with an LLM judge on one benchmark of conversational recall, not on task outcomes.
- Graph memory adds latency for a small gain.
## We adopt
Explicit, typed per-candidate operations are the right shape. Our `tools/promote.py` verdicts (add, merge, conflict, reject, deferred) map onto ADD, UPDATE(+helpful), and DELETE/NOOP. This supports DESIGN.md#learning-loop.
## We reject
Model-decided DELETE on contradiction. Contradictions go to `memory/conflicts/` with both sources and need a human or new external evidence (DESIGN.md#conflicts, R4, informed by 2310.01798). We also keep promotion gated on external verification rather than the LLM's own call.
